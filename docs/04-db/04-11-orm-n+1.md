# 04-11 ORM N+1 문제

## 개념

**N+1 문제**: ORM에서 1번의 쿼리로 N개 결과를 가져온 후, 각 결과마다 추가 쿼리를 N번 실행하는 성능 문제.

```
나쁜 예 (N+1):
  devices = Device.objects.filter(site_id=42)    ← 쿼리 1번
  for device in devices:                          ← N개
      ifaces = device.interfaces.all()            ← 쿼리 N번
  → 총 N+1번 DB 왕복

좋은 예 (1+1 또는 1):
  devices = Device.objects.prefetch_related('interfaces').filter(site_id=42)
  → 총 2번 (devices + interfaces 일괄)
```

---

## 동작 원리

### ORM의 Lazy Loading

```
Django/SQLAlchemy의 기본 동작:
  관계 객체를 실제 접근할 때 SELECT 실행 (Lazy)
  → 루프에서 접근 시 N번 쿼리 발생

Django:
  ForeignKey: 접근 시 SELECT 1회
  ManyToMany/reverse FK: all() 호출 시 SELECT 1회

SQLAlchemy:
  relationship(..., lazy='select')  ← 기본값 = Lazy
  relationship(..., lazy='joined')  ← JOIN으로 즉시 로드
  relationship(..., lazy='subquery') ← 서브쿼리로 일괄 로드
```

### 해결 방법

```
1. Eager Loading (Django: select_related, prefetch_related)
   select_related:   JOIN (ForeignKey, OneToOne)
   prefetch_related: 별도 쿼리 + Python에서 조합 (ManyToMany, reverse FK)

2. SQL 레벨 JOIN
   직접 JOIN 쿼리 작성 (annotate, values, raw)

3. Batch Loading
   IN 절로 일괄 조회: WHERE device_id IN (1,2,3,...,N)

4. GraphQL DataLoader 패턴
   여러 요청을 모아서 한 번에 처리 (Batching)
```

### select_related vs prefetch_related

```
select_related (JOIN):
  Device.objects.select_related('site')
  → SELECT d.*, s.* FROM devices d JOIN sites s ON d.site_id = s.id
  → 단일 쿼리, ForeignKey/OneToOne에 적합

prefetch_related (2 queries):
  Device.objects.prefetch_related('interfaces')
  → SELECT * FROM devices WHERE site_id=42
  → SELECT * FROM interfaces WHERE device_id IN (1,2,3,...,N)
  → Python에서 매핑
  → ManyToMany, reverse FK에 적합
```

## 예시 코드 (Python)

```python
import sqlite3
import time
from typing import Optional


# ── 데이터베이스 설정 ─────────────────────────────────

def setup(conn):
    conn.executescript("""
        CREATE TABLE sites (
            id   INTEGER PRIMARY KEY,
            name TEXT
        );
        CREATE TABLE devices (
            id      INTEGER PRIMARY KEY,
            hostname TEXT,
            site_id INTEGER,
            FOREIGN KEY (site_id) REFERENCES sites(id)
        );
        CREATE TABLE interfaces (
            id        INTEGER PRIMARY KEY,
            device_id INTEGER,
            name      TEXT,
            status    TEXT,
            FOREIGN KEY (device_id) REFERENCES devices(id)
        );

        INSERT INTO sites VALUES (1,'HQ'),(2,'Branch1'),(3,'Branch2');
    """)

    # 장비 50개, 각 4개 인터페이스
    conn.executemany("INSERT INTO devices VALUES (?,?,?)",
        [(i, f"device-{i:03d}", (i % 3) + 1) for i in range(50)])
    conn.executemany("INSERT INTO interfaces VALUES (?,?,?,?)", [
        (i * 4 + j, i, f"Gi0/{j}", "up" if j % 3 != 0 else "down")
        for i in range(50) for j in range(4)
    ])
    conn.commit()


# ── ORM 시뮬레이션 클래스 ────────────────────────────

class QueryCounter:
    """쿼리 횟수 추적"""
    def __init__(self, conn):
        self.conn   = conn
        self.count  = 0
        self.queries = []

    def execute(self, sql, params=()):
        self.count += 1
        self.queries.append(sql[:60])
        return self.conn.execute(sql, params)


class OrmSimulator:
    """
    Django ORM N+1 문제 시뮬레이션
    실제 ORM 없이 패턴 시연
    """

    def __init__(self, conn):
        self.qc = QueryCounter(conn)

    def reset(self):
        self.qc.count  = 0
        self.qc.queries = []

    # ── N+1 문제 발생 (Lazy Loading) ─────────────────

    def get_devices_with_interfaces_n1(self, site_id: int) -> list:
        """
        나쁜 패턴: 각 device마다 interfaces를 별도 조회
        1 + N 번 쿼리 발생
        """
        # 쿼리 1: devices 목록
        devices = self.qc.execute(
            "SELECT id, hostname FROM devices WHERE site_id=?", (site_id,)
        ).fetchall()

        result = []
        for dev_id, hostname in devices:
            # 쿼리 N: 각 device마다 interfaces 조회
            ifaces = self.qc.execute(
                "SELECT name, status FROM interfaces WHERE device_id=?",
                (dev_id,)
            ).fetchall()
            result.append({"id": dev_id, "hostname": hostname, "interfaces": ifaces})

        return result

    # ── 해결 1: JOIN ──────────────────────────────────

    def get_devices_with_interfaces_join(self, site_id: int) -> list:
        """
        좋은 패턴 1: JOIN으로 한 번에 조회 (select_related 유사)
        쿼리 1번
        """
        rows = self.qc.execute("""
            SELECT d.id, d.hostname, i.name, i.status
            FROM devices d
            LEFT JOIN interfaces i ON d.id = i.device_id
            WHERE d.site_id = ?
            ORDER BY d.id, i.name
        """, (site_id,)).fetchall()

        # Python에서 그룹핑
        result = {}
        for dev_id, hostname, iface_name, iface_status in rows:
            if dev_id not in result:
                result[dev_id] = {"id": dev_id, "hostname": hostname, "interfaces": []}
            if iface_name:
                result[dev_id]["interfaces"].append((iface_name, iface_status))

        return list(result.values())

    # ── 해결 2: prefetch_related (IN절 일괄 조회) ─────

    def get_devices_with_interfaces_prefetch(self, site_id: int) -> list:
        """
        좋은 패턴 2: prefetch_related 유사
        devices 1번 + interfaces IN절 1번 = 2번 쿼리
        """
        # 쿼리 1: devices
        devices = self.qc.execute(
            "SELECT id, hostname FROM devices WHERE site_id=?", (site_id,)
        ).fetchall()

        if not devices:
            return []

        dev_ids = [d[0] for d in devices]
        placeholders = ",".join("?" * len(dev_ids))

        # 쿼리 2: 모든 device의 interfaces 일괄 조회 (IN절)
        ifaces_rows = self.qc.execute(
            f"SELECT device_id, name, status FROM interfaces "
            f"WHERE device_id IN ({placeholders})",
            dev_ids
        ).fetchall()

        # Python에서 매핑
        iface_map: dict = {}
        for dev_id, name, status in ifaces_rows:
            iface_map.setdefault(dev_id, []).append((name, status))

        return [
            {"id": d[0], "hostname": d[1],
             "interfaces": iface_map.get(d[0], [])}
            for d in devices
        ]

    # ── 성능 비교 ────────────────────────────────────

    def compare(self, site_id: int):
        methods = [
            ("N+1 (Lazy Loading)",      self.get_devices_with_interfaces_n1),
            ("JOIN (select_related)",   self.get_devices_with_interfaces_join),
            ("Prefetch IN (prefetch_related)", self.get_devices_with_interfaces_prefetch),
        ]

        print(f"  [사이트 {site_id} 장비 조회 비교]")
        for label, method in methods:
            self.reset()
            start = time.perf_counter()
            result = method(site_id)
            elapsed = (time.perf_counter() - start) * 1000
            dev_cnt  = len(result)
            iface_cnt = sum(len(d["interfaces"]) for d in result)
            print(f"  {label:40s}: {self.qc.count:3d}회 쿼리, "
                  f"{elapsed:.2f}ms, "
                  f"장비 {dev_cnt}개, 인터페이스 {iface_cnt}개")


# ── DataLoader 패턴 (GraphQL/Batching) ───────────────

class DataLoader:
    """
    N+1을 해결하는 Batching 패턴
    여러 개별 요청을 모아서 한 번에 처리
    """

    def __init__(self, conn):
        self.conn    = conn
        self._queue: list = []
        self._cache: dict = {}

    def load(self, device_id: int) -> dict:
        """device_id로 인터페이스 로드 요청 등록"""
        self._queue.append(device_id)
        return None   # 실제 DataLoader는 Promise/Future 반환

    def dispatch(self) -> dict:
        """큐에 모인 ID를 한 번에 조회 (배치 처리)"""
        if not self._queue:
            return {}
        unique_ids = list(set(self._queue))
        placeholders = ",".join("?" * len(unique_ids))
        rows = self.conn.execute(
            f"SELECT device_id, name, status FROM interfaces "
            f"WHERE device_id IN ({placeholders})",
            unique_ids
        ).fetchall()
        result: dict = {}
        for dev_id, name, status in rows:
            result.setdefault(dev_id, []).append({"name": name, "status": status})
        self._queue.clear()
        return result


# ── 실행 ─────────────────────────────────────────────

conn = sqlite3.connect(":memory:")
setup(conn)

print("=== N+1 문제 비교 ===")
orm = OrmSimulator(conn)
orm.compare(site_id=1)

print("\n=== DataLoader (Batching) ===")
loader = DataLoader(conn)
device_ids = [1, 3, 5, 7, 9]

# 각 device에 대해 개별로 요청 등록
for dev_id in device_ids:
    loader.load(dev_id)

# 한 번에 일괄 처리 (1회 쿼리)
batch_result = loader.dispatch()
print(f"  {len(device_ids)}개 장비 인터페이스 — 1회 쿼리:")
for dev_id in device_ids:
    ifaces = batch_result.get(dev_id, [])
    up_cnt = sum(1 for i in ifaces if i["status"] == "up")
    print(f"  device {dev_id}: {len(ifaces)}개 인터페이스 (UP={up_cnt})")
```

## 면접 예상 질문

- Q: N+1 문제란? 왜 발생하나?
  A: ORM의 Lazy Loading 기본값 때문. 1번 쿼리로 N개 결과를 가져온 후, 각 관계 객체 접근 시 N번 추가 쿼리가 실행됨. 총 N+1번 DB 왕복. 코드에서는 보이지 않지만 DB에는 폭발적 쿼리 발생. ORM 로그나 DB slow query log로 확인.

- Q: N+1 해결 방법을 설명하라.
  A: ① Eager Loading — Django의 select_related(JOIN), prefetch_related(IN절 일괄). SQLAlchemy의 joinedload/subqueryload. ② 직접 JOIN 쿼리 작성. ③ IN절 배치 조회. ④ DataLoader 패턴(GraphQL — 개별 요청을 모아 배치 처리). 근본 해결은 쿼리 계획을 이해하고 ORM이 발생시키는 SQL을 직접 확인하는 것.

- Q: select_related와 prefetch_related의 차이는?
  A: select_related — SQL JOIN으로 단일 쿼리. ForeignKey/OneToOne 관계(1:1 또는 N:1)에 적합. prefetch_related — devices 조회 후 해당 ID 목록으로 related 테이블 IN절 조회, Python에서 매핑. ManyToMany/reverse ForeignKey(1:N)에 적합. JOIN하면 행 수 폭발하는 경우(1:N) prefetch가 낫다.
