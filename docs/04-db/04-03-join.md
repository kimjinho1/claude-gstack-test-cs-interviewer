# 04-03 조인 (Inner, Outer, Cross, Self)

## 개념

**JOIN**: 두 개 이상의 테이블을 공통 컬럼(키)으로 연결해 하나의 결과 집합으로 만드는 연산.

---

## 동작 원리

### 조인 종류

```
테이블 A (devices):        테이블 B (interfaces):
id | hostname              id | device_id | name | status
1  | sw-core-01            1  | 1         | Gi0/0 | up
2  | sw-dist-01            2  | 1         | Gi0/1 | down
3  | ap-floor1             3  | 2         | Gi0/0 | up
                           (device_id=3 없음)
```

**INNER JOIN** — 양쪽 모두 일치하는 행만:
```sql
SELECT d.hostname, i.name
FROM devices d INNER JOIN interfaces i ON d.id = i.device_id

결과:
  sw-core-01 | Gi0/0
  sw-core-01 | Gi0/1
  sw-dist-01 | Gi0/0
  (ap-floor1는 interfaces 없어 제외)
```

**LEFT OUTER JOIN** — 왼쪽 테이블 모두 + 오른쪽 일치하면 포함:
```sql
SELECT d.hostname, i.name
FROM devices d LEFT JOIN interfaces i ON d.id = i.device_id

결과:
  sw-core-01 | Gi0/0
  sw-core-01 | Gi0/1
  sw-dist-01 | Gi0/0
  ap-floor1  | NULL   ← 인터페이스 없어도 장비 행은 포함
```

**RIGHT OUTER JOIN** — 오른쪽 테이블 모두 (LEFT의 반대):
```sql
실무에서 잘 안 씀 — LEFT JOIN으로 테이블 순서 바꿔 동일 표현 가능
```

**FULL OUTER JOIN** — 양쪽 모두 포함 (SQLite 미지원, MySQL도 미지원):
```sql
SELECT d.hostname, i.name
FROM devices d FULL OUTER JOIN interfaces i ON d.id = i.device_id

결과: LEFT + RIGHT 합집합 (NULL 포함)
```

**CROSS JOIN** — 카르테시안 곱 (모든 조합):
```sql
SELECT d.hostname, v.vlan_id
FROM devices d CROSS JOIN vlans v

결과: devices 3행 × vlans N행 = 3N행
용도: 테스트 데이터 생성, 날짜/시간 조합 테이블
```

**SELF JOIN** — 같은 테이블끼리:
```sql
-- 상위 스위치와 하위 스위치 관계 (계층 구조)
SELECT child.hostname AS 하위, parent.hostname AS 상위
FROM devices child
JOIN devices parent ON child.uplink_device_id = parent.id
```

### 조인 알고리즘 (내부 구현)

```
Nested Loop Join: O(N×M)
  for each row in outer:
      for each row in inner:
          if condition: output
  → 소용량 또는 inner 테이블에 인덱스 있을 때

Hash Join: O(N+M)
  1. 작은 테이블을 해시맵으로 만듦
  2. 큰 테이블을 스캔하며 해시 조회
  → 인덱스 없는 대용량 조인에 효율적
  → PostgreSQL, MySQL 8.0+에서 지원

Sort-Merge Join: O(N log N + M log M)
  1. 양쪽 정렬
  2. 두 포인터로 병합
  → 이미 정렬된 인덱스 있을 때 효율적
```

## 예시 코드 (Python)

```python
import sqlite3
from collections import defaultdict


# ── 테이블 설정 ───────────────────────────────────────

def setup(conn):
    conn.executescript("""
        CREATE TABLE devices (
            id       INTEGER PRIMARY KEY,
            hostname TEXT,
            type     TEXT,
            site     TEXT
        );
        CREATE TABLE interfaces (
            id        INTEGER PRIMARY KEY,
            device_id INTEGER,
            name      TEXT,
            status    TEXT,
            vlan_id   INTEGER
        );
        CREATE TABLE vlans (
            vlan_id INTEGER PRIMARY KEY,
            name    TEXT
        );

        INSERT INTO devices VALUES (1,'sw-core-01','switch','HQ');
        INSERT INTO devices VALUES (2,'sw-dist-01','switch','HQ');
        INSERT INTO devices VALUES (3,'ap-floor1','ap','HQ');

        INSERT INTO interfaces VALUES (1,1,'Gi0/0','up',10);
        INSERT INTO interfaces VALUES (2,1,'Gi0/1','down',20);
        INSERT INTO interfaces VALUES (3,2,'Gi0/0','up',10);
        INSERT INTO interfaces VALUES (4,2,'Gi0/1','up',30);

        INSERT INTO vlans VALUES (10,'Management');
        INSERT INTO vlans VALUES (20,'Data');
        -- vlan 30은 없음 (VLAN 테이블 불일치 시나리오)
    """)
    conn.commit()


# ── JOIN 종류 시연 ─────────────────────────────────────

def join_demo(conn):
    print("[INNER JOIN] 장비 + 활성 인터페이스:")
    rows = conn.execute("""
        SELECT d.hostname, i.name, i.status, i.vlan_id
        FROM devices d
        INNER JOIN interfaces i ON d.id = i.device_id
        WHERE i.status = 'up'
        ORDER BY d.hostname, i.name
    """).fetchall()
    for r in rows:
        print(f"  {r[0]:15s} {r[1]:8s} {r[2]:5s} VLAN={r[3]}")

    print("\n[LEFT JOIN] 인터페이스 없는 장비도 포함:")
    rows = conn.execute("""
        SELECT d.hostname, COUNT(i.id) AS iface_cnt
        FROM devices d
        LEFT JOIN interfaces i ON d.id = i.device_id
        GROUP BY d.id, d.hostname
        ORDER BY d.hostname
    """).fetchall()
    for r in rows:
        print(f"  {r[0]:15s} 인터페이스 {r[1]}개")

    print("\n[3-table JOIN] 인터페이스 + VLAN 이름:")
    rows = conn.execute("""
        SELECT d.hostname, i.name, i.vlan_id,
               COALESCE(v.name, '미정의 VLAN') AS vlan_name
        FROM devices d
        JOIN interfaces i ON d.id = i.device_id
        LEFT JOIN vlans v ON i.vlan_id = v.vlan_id
        ORDER BY d.hostname, i.name
    """).fetchall()
    for r in rows:
        print(f"  {r[0]:15s} {r[1]:8s} VLAN={r[2]:3d} ({r[3]})")

    print("\n[SELF JOIN] 사이트별 스위치 페어링 (같은 사이트):")
    rows = conn.execute("""
        SELECT a.hostname AS sw1, b.hostname AS sw2, a.site
        FROM devices a
        JOIN devices b ON a.site = b.site AND a.id < b.id
        WHERE a.type = 'switch' AND b.type = 'switch'
    """).fetchall()
    for r in rows:
        print(f"  {r[0]} ↔ {r[1]} (사이트: {r[2]})")


# ── Hash Join 직접 구현 ───────────────────────────────

def hash_join(outer: list[dict], inner: list[dict],
              outer_key: str, inner_key: str) -> list[dict]:
    """
    Hash Join 알고리즘 직접 구현
    작은 테이블(inner)을 해시맵으로 만들고 outer를 스캔
    O(N+M) — 인덱스 없는 대용량 조인에 효율적
    """
    # Build phase: inner 테이블 해시맵 구성
    hash_table: dict[any, list[dict]] = defaultdict(list)
    for row in inner:
        hash_table[row[inner_key]].append(row)

    # Probe phase: outer 테이블 스캔
    results = []
    for outer_row in outer:
        key = outer_row[outer_key]
        for inner_row in hash_table.get(key, []):
            results.append({**outer_row, **inner_row})

    return results


def hash_join_demo():
    devices = [
        {"dev_id": 1, "hostname": "sw-core-01"},
        {"dev_id": 2, "hostname": "sw-dist-01"},
        {"dev_id": 3, "hostname": "ap-floor1"},   # 인터페이스 없음
    ]
    interfaces = [
        {"iface_dev_id": 1, "name": "Gi0/0", "status": "up"},
        {"iface_dev_id": 1, "name": "Gi0/1", "status": "down"},
        {"iface_dev_id": 2, "name": "Gi0/0", "status": "up"},
    ]

    result = hash_join(devices, interfaces, "dev_id", "iface_dev_id")
    print("\n[Hash Join 구현]")
    for r in result:
        print(f"  {r['hostname']:15s} {r['name']:8s} {r['status']}")


# ── 실행 ─────────────────────────────────────────────

conn = sqlite3.connect(":memory:")
setup(conn)

print("=== JOIN 종류 시연 ===")
join_demo(conn)

print("\n=== Hash Join 직접 구현 ===")
hash_join_demo()
```

## 면접 예상 질문

- Q: INNER JOIN과 LEFT JOIN의 차이는?
  A: INNER JOIN은 양쪽 테이블에서 일치하는 행만 반환 — 어느 한쪽에 없으면 제외. LEFT JOIN은 왼쪽 테이블의 모든 행을 반환 + 오른쪽 일치 행 없으면 NULL. 인터페이스 없는 장비도 보고 싶으면 LEFT JOIN 사용.

- Q: 조인 알고리즘의 종류와 선택 기준은?
  A: Nested Loop — 작은 테이블 + inner에 인덱스 있을 때. Hash Join — 인덱스 없고 대용량, O(N+M) 메모리 활용. Sort-Merge — 이미 정렬된 인덱스가 있을 때. 옵티마이저가 통계 기반으로 자동 선택. EXPLAIN으로 확인 가능.

- Q: 조인 성능 개선 방법은?
  A: ① 조인 컬럼에 인덱스 생성 (외래키에 자동 인덱스 없는 DB도 있음). ② 필요한 컬럼만 SELECT (SELECT *는 I/O 낭비). ③ WHERE 조건으로 조인 전 행 수 줄이기. ④ 작은 테이블을 inner로 배치 (Nested Loop). ⑤ 서브쿼리 대신 JOIN 사용 (옵티마이저가 더 잘 최적화).
