# 03-01 시간/공간 복잡도 (Big-O)

## 개념

알고리즘의 **효율성**을 입력 크기 N에 대한 함수로 표현. 최악의 경우(Upper Bound) 기준.

```
Big-O 표기 = 가장 빠르게 증가하는 항만 남김 (상수 무시)
  3N² + 5N + 100  →  O(N²)
  2N log N + N    →  O(N log N)
```

---

## 복잡도 등급 (빠름 → 느림)

```
O(1)       상수     배열 인덱스 접근, 해시맵 조회
O(log N)   로그     이진 탐색, 균형 BST 탐색
O(N)       선형     배열 순회, 선형 탐색
O(N log N) 선형로그 병합 정렬, 퀵 정렬 평균
O(N²)      이차     버블 정렬, 삽입 정렬, 이중 루프
O(2^N)     지수     재귀 피보나치, 부분집합 탐색
O(N!)      팩토리얼 순열 생성, 외판원 문제 브루트포스
```

N=1,000 일 때 연산 횟수:

```
O(1)       →          1
O(log N)   →         10
O(N)       →      1,000
O(N log N) →     10,000
O(N²)      →  1,000,000
O(2^N)     →  2^1000 (우주 나이도 안 됨)
```

---

## 동작 원리

### 시간 복잡도

**O(1) — 상수 시간**
```python
arr = [1, 2, 3, 4, 5]
arr[3]          # 인덱스 직접 접근 → 항상 1번
d = {"a": 1}
d["a"]          # 해시맵 → 평균 O(1)
```

**O(log N) — 로그 시간**
```
이진 탐색: 매 단계마다 탐색 범위 절반
N=1024 → 10번만에 찾음 (log₂1024 = 10)

[1, 3, 5, 7, 9, 11, 13, 15]  target=7
 ↑───────────↑ 중간=7  → 찾음! (1번)
```

**O(N log N) — 왜 정렬의 하한선인가**
```
비교 기반 정렬의 이론적 하한: Ω(N log N)
이유: N개 원소의 모든 순열 = N! 가지
     결정 트리의 리프 수 ≥ N!
     트리 높이 ≥ log₂(N!) ≈ N log N

→ 퀵 정렬, 병합 정렬이 O(N log N) → 비교 기반 최적
```

**O(N²) — 이중 루프**
```python
# 모든 쌍 비교
for i in range(N):
    for j in range(N):
        ...  # N × N = N² 번
```

### 공간 복잡도

```
O(1): 입력 외 추가 변수 상수 개 (in-place 정렬)
O(N): 입력 크기에 비례한 공간 (복사 배열, 재귀 스택)
O(N²): 2D 배열, N×N 행렬

재귀 함수의 공간 복잡도:
  재귀 깊이 = 스택 프레임 개수
  이진 탐색 재귀 → O(log N) 스택
  피보나치 재귀  → O(N) 스택
```

### Best / Average / Worst

```
퀵 정렬:
  Best:    O(N log N)  — 피벗이 항상 중앙값
  Average: O(N log N)  — 랜덤 피벗
  Worst:   O(N²)       — 이미 정렬된 배열 + 맨 앞 피벗

해시맵:
  Average: O(1)   — 충돌 없음
  Worst:   O(N)   — 모든 키가 같은 버킷 (최악의 해시 함수)
```

## 예시 코드 (Python)

```python
import time
import random


def measure(func, *args) -> float:
    start = time.perf_counter()
    func(*args)
    return time.perf_counter() - start


# ── 각 복잡도 비교 ────────────────────────────────────

def o1(arr):           return arr[0]
def ologn(arr, t):     # 이진 탐색
    lo, hi = 0, len(arr) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if arr[mid] == t: return mid
        elif arr[mid] < t: lo = mid + 1
        else: hi = mid - 1
    return -1
def on(arr):           return sum(arr)
def on2(arr):
    count = 0
    for i in arr:
        for j in arr:
            count += 1
    return count


sizes = [100, 1000, 5000]
for N in sizes:
    arr = sorted(range(N))
    t1 = measure(o1, arr)
    t2 = measure(ologn, arr, N//2)
    t3 = measure(on, arr)
    # N²는 N=5000이면 너무 느리니 N=1000까지만
    if N <= 1000:
        t4 = measure(on2, arr)
        print(f"N={N:5d}: O(1)={t1*1e6:.2f}μs  O(logN)={t2*1e6:.2f}μs  "
              f"O(N)={t3*1e6:.2f}μs  O(N²)={t4*1000:.2f}ms")
    else:
        print(f"N={N:5d}: O(1)={t1*1e6:.2f}μs  O(logN)={t2*1e6:.2f}μs  "
              f"O(N)={t3*1e6:.2f}μs")


# ── 실무 적용: NMS에서 장비 목록 탐색 ────────────────

devices = [{"id": i, "ip": f"192.168.1.{i%254+1}"} for i in range(10000)]

# O(N) 선형 탐색
def find_linear(devices, target_id):
    for d in devices:
        if d["id"] == target_id:
            return d
    return None

# O(1) 해시맵 조회
device_map = {d["id"]: d for d in devices}
def find_hash(device_id):
    return device_map.get(device_id)

N = 10000
t_linear = measure(find_linear, devices, N-1)
t_hash   = measure(find_hash, N-1)
print(f"\n장비 탐색 (N={N}):")
print(f"  선형 탐색 O(N): {t_linear*1000:.3f}ms")
print(f"  해시맵   O(1): {t_hash*1000:.3f}ms")
print(f"  속도 차이: {t_linear/t_hash:.0f}배")
```

## 면접 예상 질문

- Q: O(N log N)이 비교 기반 정렬의 하한인 이유는?
  A: N개 원소 정렬의 경우의 수는 N!. 비교 결과로 경우의 수를 구분하는 결정 트리의 리프 수 ≥ N!이므로 트리 높이(=비교 횟수) ≥ log₂(N!) ≈ N log N. 따라서 비교만으로 정렬하면 O(N log N)이 최선. 카운팅 정렬 등 비교를 안 쓰는 정렬은 O(N)도 가능.

- Q: 최악/평균 복잡도가 다른 알고리즘 예시는?
  A: 퀵 정렬 — 평균 O(N log N), 최악 O(N²)(이미 정렬된 배열에서 맨 앞 피벗). 해시맵 — 평균 O(1), 최악 O(N)(모든 키 충돌). 실무에서 랜덤 피벗/좋은 해시 함수로 최악 회피.

- Q: 공간 복잡도 O(1)인 정렬은?
  A: 버블 정렬, 선택 정렬, 삽입 정렬, 힙 정렬. 병합 정렬은 O(N) 추가 공간. 퀵 정렬은 재귀 스택 O(log N)~O(N).
