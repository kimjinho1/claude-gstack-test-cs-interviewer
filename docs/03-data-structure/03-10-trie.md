# 03-10 Trie (트라이)

## 개념

**Trie**: 문자열을 공통 접두사(prefix)별로 트리 구조에 저장. **문자열 탐색 O(L)** (L=문자열 길이, N과 무관).

```
삽입: "ap", "apple", "apt", "apply", "bat"

        (root)
        /    \
       a      b
       |      |
       p      a
      /|\     |
     *  p  t  t
        |  |  *
        l  *
       / \
      e   y
      *   *

* = 단어 끝 표시
"apple" 탐색: root→a→p→p→l→e (6번 이동) = O(6) = O(L)
```

---

## 동작 원리

### 왜 해시맵보다 Trie가 유리한가

```
N개의 문자열, 각 길이 L

해시맵:
  탐색: O(L) — 해시 계산에 문자열 전체 읽어야 함
  접두사 탐색: 불가 — "app"으로 시작하는 모든 단어 찾기 불가
  정렬된 순서: 불가

Trie:
  탐색:     O(L) — 동일
  접두사 탐색: O(L + K) — 접두사 노드까지 이동 후 DFS (K=결과 수)
  정렬된 순서: 자동으로 알파벳 순 (자식 정렬 시)
  공통 접두사 저장: 메모리 효율적

주요 사용처:
  - 자동완성 (Auto-complete)
  - IP 라우팅 (최장 프리픽스 매칭)
  - 사전 검색
  - 스펠 체크
```

### IP 라우팅에서의 Trie (Radix/Patricia Tree)

```
라우팅 테이블:
  192.168.1.0/24  → Port 1
  192.168.0.0/16  → Port 2
  10.0.0.0/8      → Port 3
  0.0.0.0/0       → Port 4 (default)

목적지 192.168.1.5 → 가장 긴 프리픽스 매칭:
  /0  → 매칭
  /16 → 매칭
  /24 → 매칭 (가장 길다!)
  → Port 1 사용

실제 라우터: Patricia Trie (압축 트리) 사용
  → 긴 공통 prefix는 하나의 간선으로 압축
```

## 예시 코드 (Python)

```python
from collections import defaultdict
from typing import Optional


# ── Trie 구현 ─────────────────────────────────────────

class TrieNode:
    def __init__(self):
        self.children: dict[str, TrieNode] = {}
        self.is_end = False
        self.count  = 0   # 이 노드를 지나간 단어 수 (prefix count)


class Trie:
    def __init__(self):
        self.root = TrieNode()

    def insert(self, word: str):          # O(L)
        node = self.root
        for ch in word:
            if ch not in node.children:
                node.children[ch] = TrieNode()
            node = node.children[ch]
            node.count += 1
        node.is_end = True

    def search(self, word: str) -> bool:  # O(L)
        node = self._get_node(word)
        return node is not None and node.is_end

    def starts_with(self, prefix: str) -> bool:  # O(L)
        return self._get_node(prefix) is not None

    def count_prefix(self, prefix: str) -> int:  # O(L)
        """prefix로 시작하는 단어 수"""
        node = self._get_node(prefix)
        return node.count if node else 0

    def _get_node(self, prefix: str) -> Optional[TrieNode]:
        node = self.root
        for ch in prefix:
            if ch not in node.children:
                return None
            node = node.children[ch]
        return node

    def autocomplete(self, prefix: str, limit: int = 5) -> list[str]:
        """prefix로 시작하는 단어 목록 (DFS) — O(L + K)"""
        node = self._get_node(prefix)
        if node is None:
            return []
        results = []
        self._dfs(node, prefix, results, limit)
        return results

    def _dfs(self, node: TrieNode, current: str, results: list, limit: int):
        if len(results) >= limit:
            return
        if node.is_end:
            results.append(current)
        for ch in sorted(node.children):  # 알파벳 순
            self._dfs(node.children[ch], current + ch, results, limit)

    def delete(self, word: str) -> bool:  # O(L)
        def _del(node, word, depth):
            if depth == len(word):
                if not node.is_end:
                    return False
                node.is_end = False
                return len(node.children) == 0
            ch = word[depth]
            if ch not in node.children:
                return False
            should_delete = _del(node.children[ch], word, depth + 1)
            if should_delete:
                del node.children[ch]
                return not node.is_end and len(node.children) == 0
            return False
        return _del(self.root, word, 0)


# ── IP 라우팅 Trie (최장 프리픽스 매칭) ─────────────

class IPRoutingTrie:
    """
    IP 주소를 비트 Trie로 관리
    최장 프리픽스 매칭(Longest Prefix Matching) — O(32) = O(1)
    실제 라우터의 FIB(Forwarding Information Base) 개념
    """
    class Node:
        def __init__(self):
            self.children = [None, None]  # 0, 1
            self.next_hop: Optional[str] = None
            self.prefix_len: int = 0

    def __init__(self):
        self.root = self.Node()

    def add_route(self, prefix: str, prefix_len: int, next_hop: str):
        """예: "192.168.1.0", 24, "eth0" """
        bits = self._ip_to_bits(prefix)
        node = self.root
        for i in range(prefix_len):
            bit = int(bits[i])
            if node.children[bit] is None:
                node.children[bit] = self.Node()
            node = node.children[bit]
        node.next_hop = next_hop
        node.prefix_len = prefix_len

    def lookup(self, ip: str) -> Optional[str]:
        """최장 프리픽스 매칭 — O(32)"""
        bits = self._ip_to_bits(ip)
        node = self.root
        best_hop = None
        for bit_str in bits:
            bit = int(bit_str)
            if node.children[bit] is None:
                break
            node = node.children[bit]
            if node.next_hop:
                best_hop = node.next_hop   # 더 긴 매칭이 나오면 갱신
        return best_hop

    @staticmethod
    def _ip_to_bits(ip: str) -> str:
        parts = ip.split(".")
        return "".join(f"{int(p):08b}" for p in parts)


# ── 실행 ─────────────────────────────────────────────

print("=== Trie 자동완성 ===")
trie = Trie()
words = ["switch", "switchport", "switchover",
         "snmp", "snmpwalk", "snmptrap",
         "spanning", "spanning-tree",
         "show", "shutdown"]
for w in words:
    trie.insert(w)

print(f"  'sw' 자동완성: {trie.autocomplete('sw')}")
print(f"  'snmp' 자동완성: {trie.autocomplete('snmp')}")
print(f"  'snmp' 접두사 단어 수: {trie.count_prefix('snmp')}")
print(f"  'switchport' 탐색: {trie.search('switchport')}")
print(f"  'switch' 탐색: {trie.search('switch')}")
trie.delete("switch")
print(f"  'switch' 삭제 후: {trie.search('switch')}")
print(f"  'switchport' 여전히 있음: {trie.search('switchport')}")

print("\n=== IP 라우팅 Trie ===")
routing = IPRoutingTrie()
routing.add_route("0.0.0.0",     0,  "default-gw")
routing.add_route("192.168.0.0", 16, "vlan-interface")
routing.add_route("192.168.1.0", 24, "eth0")
routing.add_route("192.168.1.128", 25, "eth1")  # 더 구체적인 경로

test_ips = ["192.168.1.1", "192.168.1.200", "192.168.2.1", "10.0.0.1"]
for ip in test_ips:
    print(f"  {ip:20s} → {routing.lookup(ip)}")
```

## 면접 예상 질문

- Q: Trie의 시간 복잡도가 O(L)인 이유는?
  A: 탐색은 문자열의 각 문자를 따라 트리를 한 단계씩 내려가므로 O(L). 전체 단어 수 N에 무관. 반면 해시맵도 해시 계산에 O(L)이 걸리므로 탐색 속도는 비슷. Trie의 진짜 강점은 접두사 탐색과 자동완성 — 해시맵은 이게 불가능.

- Q: IP 라우팅에서 Trie를 사용하는 이유는?
  A: 최장 프리픽스 매칭(LPM). 라우팅 테이블에서 목적지 IP와 가장 길게 일치하는 경로를 찾아야 함. Trie로 IP 비트를 따라가며 마지막으로 매칭된 경로를 기록하면 O(32)(IPv4) = O(1)로 해결. 실제 라우터의 FIB는 Patricia Trie(압축 Trie) 사용.

- Q: Trie의 단점은?
  A: 메모리. 각 노드가 자식 포인터 배열(알파벳 26개면 26개 포인터)을 가짐 → 단어 수에 비해 노드가 많고 포인터 공간 낭비. 해결: HashMap 기반 자식(실제 있는 자식만 저장), Radix/Patricia Trie(공통 경로 압축), DAWG(공통 suffix도 공유).
