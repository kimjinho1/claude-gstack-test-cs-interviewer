# 01-06 DNS (Domain Name System)

## 개념

도메인 이름(`google.com`)을 IP 주소(`142.250.196.46`)로 변환하는 **분산 계층 시스템**.
사람이 기억하기 쉬운 이름 ↔ 기계가 사용하는 IP 주소를 매핑.

- 프로토콜: UDP 53번 포트 (응답이 512byte 초과 시 TCP로 전환)
- 전 세계 분산 구조 → 단일 장애점 없음

---

## 동작 원리

### DNS 계층 구조

```
.  (Root)                ← 전 세계 13개 Root DNS 서버
├── com  (TLD)           ← .com 담당 TLD DNS
│   ├── google.com       ← 구글이 직접 관리하는 Authoritative DNS
│   └── naver.com
├── net
└── kr
    └── co.kr
```

### 조회 흐름 (www.google.com 처음 접속 시)

```
PC              Local DNS        Root DNS    TLD(.com)   Auth(google)
│               │                │           │               │
│─"www.google.com?"──────────────▶│           │               │
│               │ (캐시 없음)      │           │               │
│               │─"com 담당 누구?"─▶│           │               │
│               │◀─"TLD 주소 알려줌"─│           │               │
│               │───────────────────"google 담당?"──▶│          │
│               │◀──────────────────"Auth DNS 주소"───│          │
│               │────────────────────────────────"www?"────────▶│
│               │◀───────────────────────────────"142.250.196.46"│
│◀─"142.250.196.46"──────────────│           │               │
│  TTL 동안 캐시 저장              │           │               │
```

**Recursive vs Iterative**
- **Recursive**: Local DNS가 대신 Root→TLD→Auth 다 돌아다니며 찾아줌. PC는 한 번만 요청.
- **Iterative**: 각 DNS가 "다음에 물어봐" 주소만 알려줌. 실제 요청자가 단계별로 직접 물어봄.

실제로 PC↔Local DNS는 Recursive, Local DNS↔나머지는 Iterative.

### 캐시와 TTL

DNS 응답에는 **TTL(Time To Live)** 포함. TTL만큼 캐시에 저장.

```
조회 순서:
1. PC 로컬 캐시 (hosts 파일 포함)
2. Local DNS 캐시
3. 없으면 계층 조회 시작
```

- TTL 짧음(예: 60초): IP 변경 빠르게 반영, DNS 쿼리 증가
- TTL 길음(예: 86400초=1일): DNS 부하 낮음, IP 변경 반영 느림
- 스위치/AP 관리 도메인 IP 변경 시 → TTL 만료 전까진 구 IP로 접속

## 주요 DNS 레코드 타입

| 레코드 | 역할 | 예시 |
|--------|------|------|
| A | 도메인 → IPv4 주소 | `api.switch.local → 192.168.99.10` |
| AAAA | 도메인 → IPv6 주소 | `google.com → 2607:f8b0::` |
| CNAME | 도메인 → 도메인 (별칭) | `www.google.com → google.com` |
| MX | 메일 서버 지정 | `gmail.com → mail.google.com` |
| NS | 네임서버 지정 | `google.com → ns1.google.com` |
| PTR | IP → 도메인 (역방향 조회) | `192.168.99.10 → sw-core-01.local` |
| TXT | 텍스트 정보 | SPF, DKIM (메일 인증), 도메인 소유 확인 |
| SRV | 서비스 위치 | `_http._tcp.example.com → 포트/호스트` |

**스위치/AP 관리 관점**
- A 레코드: `sw-core-01.mgmt.local → 192.168.99.1` (이름으로 장비 접속)
- PTR 레코드: Syslog/SNMP에서 IP → 장비명 역방향 변환
- 내부 DNS 서버 없으면 `/etc/hosts`에 수동 등록

## 예시 코드 (Python)

```python
import socket
import struct
import random


def parse_dns_response(data: bytes) -> list[str]:
    """DNS 응답에서 IP 주소 추출 (간단 버전)"""
    ips = []
    # 헤더 12byte 스킵, ANCOUNT(응답 수) 추출
    ancount = struct.unpack(">H", data[6:8])[0]
    offset = 12

    # Question 섹션 스킵
    while data[offset] != 0:
        if data[offset] >= 192:  # 압축 포인터
            offset += 2
            break
        offset += data[offset] + 1
    else:
        offset += 5  # null + QTYPE(2) + QCLASS(2)

    # Answer 섹션 파싱
    for _ in range(ancount):
        if data[offset] >= 192:  # 압축 포인터
            offset += 2
        else:
            while data[offset] != 0:
                offset += data[offset] + 1
            offset += 1

        rtype = struct.unpack(">H", data[offset:offset+2])[0]
        rdlength = struct.unpack(">H", data[offset+8:offset+10])[0]
        offset += 10

        if rtype == 1 and rdlength == 4:  # A 레코드
            ip = ".".join(str(b) for b in data[offset:offset+4])
            ips.append(ip)
        offset += rdlength

    return ips


def dns_query(domain: str, dns_server: str = "8.8.8.8") -> list[str]:
    """UDP DNS 쿼리 전송 및 응답 파싱"""
    # DNS 쿼리 패킷 생성
    transaction_id = random.randint(0, 65535)
    flags = 0x0100          # Recursion Desired
    qdcount = 1             # 질문 1개

    header = struct.pack(">HHHHHH", transaction_id, flags, qdcount, 0, 0, 0)

    # QNAME 인코딩: www.google.com → \x03www\x06google\x03com\x00
    qname = b""
    for part in domain.split("."):
        qname += bytes([len(part)]) + part.encode()
    qname += b"\x00"

    qtype = struct.pack(">H", 1)   # A 레코드
    qclass = struct.pack(">H", 1)  # IN (Internet)

    query = header + qname + qtype + qclass

    # UDP로 전송
    with socket.socket(socket.AF_INET, socket.SOCK_DGRAM) as s:
        s.settimeout(3)
        s.sendto(query, (dns_server, 53))
        response, _ = s.recvfrom(512)

    return parse_dns_response(response)


# Python 내장 DNS 조회 (실무에서는 이걸 씀)
def simple_dns_lookup(domain: str) -> list[str]:
    """socket.getaddrinfo로 DNS 조회"""
    results = socket.getaddrinfo(domain, None, socket.AF_INET)
    return list(set(r[4][0] for r in results))


# DNS 캐시 시뮬레이션
import time
from dataclasses import dataclass, field


@dataclass
class DnsRecord:
    domain: str
    ips: list[str]
    ttl: int
    cached_at: float = field(default_factory=time.time)

    def is_expired(self) -> bool:
        return time.time() - self.cached_at > self.ttl


class DnsCache:
    def __init__(self):
        self._cache: dict[str, DnsRecord] = {}

    def get(self, domain: str) -> list[str] | None:
        record = self._cache.get(domain)
        if record and not record.is_expired():
            remaining = record.ttl - (time.time() - record.cached_at)
            print(f"[DNS Cache] HIT: {domain} → {record.ips} (TTL 잔여 {remaining:.0f}s)")
            return record.ips
        if record:
            print(f"[DNS Cache] EXPIRED: {domain}")
            del self._cache[domain]
        return None

    def set(self, domain: str, ips: list[str], ttl: int):
        self._cache[domain] = DnsRecord(domain=domain, ips=ips, ttl=ttl)
        print(f"[DNS Cache] STORE: {domain} → {ips} (TTL={ttl}s)")


# 사용 예시
cache = DnsCache()
cache.set("sw-core-01.mgmt.local", ["192.168.99.1"], ttl=300)
cache.get("sw-core-01.mgmt.local")   # HIT
cache.get("sw-edge-01.mgmt.local")   # None (없음)

# 실제 DNS 조회
print("\n[실제 DNS 조회]")
ips = simple_dns_lookup("google.com")
print(f"google.com → {ips}")
```

## 면접 예상 질문

- Q: DNS 조회 과정을 설명하라.
  A: PC가 Local DNS에 도메인 질의 → Local DNS가 캐시 확인 → 없으면 Root DNS → TLD DNS → Authoritative DNS 순으로 Iterative 조회 → 결과를 PC에 반환 + TTL만큼 캐시 저장. PC↔Local DNS 구간은 Recursive.

- Q: DNS가 UDP를 쓰는 이유는?
  A: 대부분의 DNS 요청/응답이 512byte 이하로 짧고, 연결 수립 오버헤드 없이 빠른 응답이 중요하기 때문. 응답이 512byte 초과하거나 Zone Transfer 시에는 TCP 사용.

- Q: DNS 캐시 포이즈닝이란?
  A: 공격자가 DNS 캐시에 허위 레코드를 심는 공격. 정상 도메인 접속 시 공격자 서버로 유도 가능. 대응: DNSSEC (DNS 응답에 디지털 서명), 랜덤 소스 포트 사용.

- Q: CNAME과 A 레코드의 차이는?
  A: A 레코드는 도메인을 IP에 직접 매핑. CNAME은 도메인을 다른 도메인(별칭)에 매핑. CNAME은 추가 DNS 조회가 필요하지만 IP 변경 시 CNAME이 가리키는 도메인의 A 레코드만 수정하면 됨.

- Q: /etc/hosts와 DNS의 우선순위는?
  A: /etc/hosts가 DNS보다 먼저 조회됨. 로컬 네트워크에서 스위치/장비 이름을 hosts에 등록하면 DNS 서버 없이도 이름으로 접속 가능. 단, 해당 호스트에서만 적용.
