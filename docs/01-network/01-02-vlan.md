# 01-02 VLAN / Trunk / Access Port

## 개념

**VLAN(Virtual LAN)** : 물리 스위치 하나를 논리적으로 여러 개의 독립된 L2 네트워크로 분리하는 기술.
같은 VLAN에 속한 장비들만 L2 브로드캐스트를 공유하며, 다른 VLAN과는 L3 장비(라우터/L3 스위치)를 통해서만 통신 가능.

**필요한 이유**
- 브로드캐스트 도메인 분리 → 불필요한 트래픽 감소
- 보안 격리 → 게스트/사무실/서버망 분리
- 물리 장비 절약 → 스위치 하나로 여러 논리 네트워크 운영

---

## 동작 원리

### VLAN 할당 예시

```
스위치 포트 설정:
포트 1~3  → VLAN 10 (사무실 PC)
포트 4~6  → VLAN 20 (AP / 무선 클라이언트)
포트 7~9  → VLAN 30 (서버)
포트 10   → VLAN 99 (관리망)
포트 24   → Trunk (스위치 간 연결)
```

- VLAN 10 장비 ↔ VLAN 20 장비 : L2 통신 불가 (다른 브로드캐스트 도메인)
- VLAN 간 통신 : L3 스위치 or 라우터 경유 필수

### Access Port

단일 VLAN만 처리하는 포트. PC, AP, 서버 등 단말 연결.

```
[PC] ──── Access Port (VLAN 10) ──── [Switch]
          태그 없는 프레임 수신
          스위치 내부에서 VLAN 10 태그 붙여 처리
          전송 시 태그 제거 후 PC로 전달
```

단말(PC, AP)은 VLAN을 모름 → 일반 Ethernet 프레임만 처리.

### Trunk Port

여러 VLAN을 하나의 링크로 전달. 스위치↔스위치, 스위치↔라우터 연결.

**802.1Q 태그 구조** (4 byte 추가)
```
[Dest MAC | Src MAC | 0x8100 | PCP(3) | DEI(1) | VLAN ID(12) | EtherType | Data | FCS]
                      ↑ TPID     ↑ 우선순위                    ↑ 0~4094
```

- VLAN ID: 12bit → 0~4094 (0, 4095 예약) → **최대 4094개 VLAN**
- PCP(Priority Code Point): QoS 우선순위 (음성/영상 트래픽 우대)

### Native VLAN

Trunk 포트에서 **802.1Q 태그 없이** 전달되는 VLAN. 기본값 VLAN 1.

```
양쪽 스위치의 Native VLAN이 반드시 일치해야 함.
불일치 시 → VLAN mismatch → 트래픽 드롭 or VLAN hopping 공격 취약
```

보안상 Native VLAN을 사용하지 않는 VLAN으로 변경하는 것을 권장.

### AP 연동 구조

```
[PC]──Access(VLAN10)──[SW-Edge]──Trunk──[SW-Core]──Trunk──[AP]
                                                            │
                                             SSID "Office" → VLAN 10
                                             SSID "Guest"  → VLAN 20
                                             SSID "IoT"    → VLAN 30
```

- AP는 **Trunk 포트**로 스위치에 연결 → 여러 SSID를 여러 VLAN에 매핑 가능
- 무선 클라이언트가 "Guest" SSID 접속 → AP가 VLAN 20 태그 붙여 스위치로 전달
- 게스트 클라이언트는 VLAN 20에만 존재 → VLAN 10 사무실 PC에 접근 불가

## 예시 코드 (Python)

```python
from dataclasses import dataclass, field
from typing import Optional

@dataclass
class VlanFrame:
    """802.1Q Tagged Frame"""
    src_mac: str
    dst_mac: str
    vlan_id: Optional[int]  # None이면 untagged (Access port 프레임)
    payload: str

    def is_tagged(self) -> bool:
        return self.vlan_id is not None

    def __repr__(self):
        tag = f"VLAN{self.vlan_id}" if self.vlan_id else "untagged"
        return f"[{tag}] {self.src_mac} → {self.dst_mac} | {self.payload}"


class SwitchPort:
    """스위치 포트 (Access or Trunk)"""
    def __init__(self, port_id: int, mode: str, vlan: int = None, allowed_vlans: list = None):
        self.port_id = port_id
        self.mode = mode  # "access" or "trunk"
        self.vlan = vlan  # access mode: 소속 VLAN
        self.allowed_vlans = allowed_vlans or []  # trunk mode: 허용 VLAN 목록
        self.native_vlan = 1  # trunk mode: native VLAN


class ManagedSwitch:
    """VLAN 지원 스위치"""
    def __init__(self, name: str):
        self.name = name
        self.ports: dict[int, SwitchPort] = {}
        self.cam_table: dict[tuple, int] = {}  # (mac, vlan_id) -> port

    def add_port(self, port: SwitchPort):
        self.ports[port.port_id] = port

    def receive(self, in_port_id: int, frame: VlanFrame):
        port = self.ports[in_port_id]

        # Access 포트: 태그 없는 프레임 수신 → VLAN 태그 붙임
        if port.mode == "access":
            if frame.is_tagged():
                print(f"[{self.name}] Port{in_port_id}: Tagged frame on access port → DROP")
                return
            frame.vlan_id = port.vlan
            print(f"[{self.name}] Port{in_port_id}: Tagged as VLAN {port.vlan}")

        # Trunk 포트: 태그된 프레임 수신 → VLAN 허용 여부 확인
        elif port.mode == "trunk":
            if not frame.is_tagged():
                frame.vlan_id = port.native_vlan  # native VLAN 처리
            if frame.vlan_id not in port.allowed_vlans:
                print(f"[{self.name}] Port{in_port_id}: VLAN {frame.vlan_id} not allowed → DROP")
                return

        # MAC 학습 (mac + vlan 조합으로 학습)
        self.cam_table[(frame.src_mac, frame.vlan_id)] = in_port_id
        self._forward(in_port_id, frame)

    def _forward(self, in_port_id: int, frame: VlanFrame):
        key = (frame.dst_mac, frame.vlan_id)
        if key in self.cam_table:
            out_port_id = self.cam_table[key]
            out_port = self.ports[out_port_id]
            # Access 포트로 전달 시 태그 제거
            if out_port.mode == "access":
                frame.vlan_id = None
            print(f"[{self.name}] Unicast → Port{out_port_id} | {frame}")
        else:
            # 같은 VLAN의 모든 포트로 flooding
            print(f"[{self.name}] Flood VLAN {frame.vlan_id} → all ports except Port{in_port_id}")


# 사용 예시
sw = ManagedSwitch("SW-EDGE-01")
sw.add_port(SwitchPort(1, "access", vlan=10))   # PC
sw.add_port(SwitchPort(2, "access", vlan=20))   # 게스트 AP
sw.add_port(SwitchPort(24, "trunk", allowed_vlans=[10, 20, 30, 99]))  # 업링크

# PC에서 프레임 수신 (untagged)
pc_frame = VlanFrame("AA:BB:CC:11:22:33", "AA:BB:CC:44:55:66", vlan_id=None, payload="data")
sw.receive(in_port_id=1, frame=pc_frame)
# → VLAN 10 태그 붙고 flooding

# Trunk 포트로 VLAN 20 프레임 수신
trunk_frame = VlanFrame("AA:BB:CC:77:88:99", "FF:FF:FF:FF:FF:FF", vlan_id=20, payload="broadcast")
sw.receive(in_port_id=24, frame=trunk_frame)
# → VLAN 20 flooding (포트 2로 전달)
```

## 면접 예상 질문

- Q: VLAN을 사용하는 이유는?
  A: 브로드캐스트 도메인 분리로 불필요한 트래픽 감소, 보안 격리(부서별/용도별 망 분리), 물리 인프라 절약. 스위치 하나로 여러 논리 네트워크 운영 가능.

- Q: Access 포트와 Trunk 포트의 차이는?
  A: Access 포트는 단일 VLAN만 처리하며 단말(PC, AP)에 연결. 프레임에 태그 없음. Trunk 포트는 802.1Q 태그로 여러 VLAN을 구분해 스위치 간 링크 하나로 전달.

- Q: 802.1Q 태그는 몇 byte이고 어디에 붙는가?
  A: 4 byte. Ethernet 프레임의 Src MAC과 EtherType 사이에 삽입. TPID(0x8100) + PCP(3bit) + DEI(1bit) + VLAN ID(12bit) 구성. VLAN ID는 최대 4094개.

- Q: Native VLAN이란?
  A: Trunk 포트에서 802.1Q 태그 없이 전달되는 VLAN. 기본값 VLAN 1. 양쪽 스위치의 Native VLAN이 다르면 mismatch 발생해 트래픽 드롭 또는 VLAN hopping 보안 취약점 발생.

- Q: AP가 여러 SSID를 지원할 때 스위치와 어떻게 연동하나?
  A: AP를 Trunk 포트로 연결해 각 SSID를 별도 VLAN에 매핑. 예를 들어 "Office" SSID → VLAN 10, "Guest" SSID → VLAN 20. 무선 클라이언트가 연결되면 AP가 해당 VLAN 태그를 붙여 스위치로 전달.

## 부록: Trunk / Hybrid 포트의 다중 VLAN 통신 상세

### Trunk 포트 — 다중 VLAN 통신 흐름

**구성 예시**
```
[PC-A]──Access(VLAN10)──[SW-EDGE-01]──Trunk(VLAN10,20,99)──[SW-CORE]──Trunk──[AP]
[PC-B]──Access(VLAN10)──[SW-EDGE-02]──Trunk(VLAN10,20,99)──[SW-CORE]            │
                                                                        SSID-Office → VLAN10
                                                                        SSID-Guest  → VLAN20
```

**PC-A → PC-B 통신 (같은 VLAN 10, 다른 스위치)**

```
① PC-A (VLAN10, 192.168.10.10) → PC-B (VLAN10, 192.168.10.20) 전송
   프레임: [Dst:PC-B_MAC | Src:PC-A_MAC | data]  ← untagged

② SW-EDGE-01 수신 (Access 포트, VLAN10)
   → VLAN 10 태그 붙임
   프레임: [Dst:PC-B_MAC | Src:PC-A_MAC | VLAN10 | data]

③ SW-EDGE-01 → SW-CORE (Trunk 포트)
   PC-B_MAC 모름 → VLAN 10에 속한 모든 Trunk/Access 포트로 flooding
   프레임: [Dst:PC-B_MAC | Src:PC-A_MAC | VLAN10 | data]  ← 태그 유지

④ SW-CORE 수신 (Trunk 포트)
   VLAN 10 allowed → 통과, PC-A MAC 학습
   PC-B_MAC 모름 → VLAN 10 포트 전체 flooding
   SW-EDGE-02 방향 Trunk로 전달 (태그 유지)

⑤ SW-EDGE-02 수신 (Trunk 포트)
   VLAN 10 Access 포트(PC-B)로 전달
   → 태그 제거 후 untagged 프레임으로 PC-B에 전달

⑥ PC-B → PC-A 응답 (ARP Reply or 실제 데이터)
   역방향으로 동일하게 진행
   각 스위치가 PC-B MAC 학습 → 이후 유니캐스트로 직접 전달
```

**핵심: 태그의 생명주기**
```
PC (untagged) → [Access 포트 진입: 태그 추가] → 스위치 내부 이동 → [Trunk 포트: 태그 유지] → 스위치 이동
→ [Access 포트 출력: 태그 제거] → PC (untagged)
```
PC는 VLAN 태그를 모름. 스위치가 붙이고 떼는 것을 알아서 처리.

**VLAN 10과 VLAN 20이 같은 Trunk 선을 공유할 때**
```
Trunk 링크로 흐르는 프레임들:
─── [VLAN10 | PC-A→PC-B data] ──────────────────────▶
─── [VLAN20 | Guest→Internet data] ─────────────────▶
─── [VLAN99 | SNMP trap to NMS] ────────────────────▶

각 프레임에 VLAN ID가 태그로 박혀있어서 수신 스위치가 어느 VLAN인지 구분.
VLAN 10 프레임은 VLAN 10 포트로만, VLAN 20 프레임은 VLAN 20 포트로만 전달.
물리 선은 하나지만 논리적으로 완전히 분리된 채널처럼 동작.
```

### Hybrid 포트 — Trunk와 무엇이 다른가

Hybrid 포트는 **Huawei / H3C 계열 장비**에서 사용하는 포트 타입. Cisco에는 없음.

**Trunk vs Hybrid 차이**

| 구분 | Access | Trunk | Hybrid |
|------|--------|-------|--------|
| 소속 VLAN | 1개 | 여러 개 (모두 tagged) | 여러 개 (tagged + untagged 혼합 가능) |
| untagged 처리 | 소속 VLAN | Native VLAN 1개만 | VLAN 지정해서 여러 개 가능 |
| 주 용도 | PC/서버 단말 | 스위치 간 연결 | IP폰+PC 혼용, 특수 AP 연동 |

**Hybrid 포트가 필요한 상황: IP 전화기 + PC**

```
[PC]──[IP Phone]──Hybrid 포트──[Switch]

IP Phone: VLAN 30 (음성망) → tagged로 전달
PC:       VLAN 10 (데이터망) → untagged로 전달 (PC는 VLAN 모름)

Hybrid 포트 설정:
  - VLAN 10: untagged (PC 방향)
  - VLAN 30: tagged  (IP Phone이 붙인 태그 그대로 통과)
```

Trunk였다면 Native VLAN 하나만 untagged 처리 가능 → PC와 IP Phone 동시에 다른 VLAN으로 운용 불가.
Hybrid는 **untagged VLAN을 여러 개 지정**할 수 있어서 이런 혼용 구성이 가능.

**AP 연동에서 Hybrid 활용**

802.1Q를 지원하지 않는 구형 AP를 여러 VLAN에 붙여야 할 때:
```
Hybrid 포트 설정:
  - VLAN 10: untagged (AP가 태그를 못 붙이는 경우 기본 VLAN)
  - VLAN 20: tagged   (AP가 지원하면 tagged로)
```

**정리**
```
Trunk  = 여러 VLAN, Native VLAN 하나만 untagged
Hybrid = 여러 VLAN, untagged VLAN을 여러 개 자유롭게 지정 가능
```
실무에서 Cisco 장비만 쓰면 Hybrid 개념 불필요. Huawei/H3C 장비 연동하거나 면접에서 나올 수 있음.

### VLAN에 IP 주소를 할당하면 L2야, L3야?

**VLAN 자체는 L2. IP를 할당하는 순간 L3 기능이 얹히는 것.**

스위치에서 VLAN에 IP를 넣는 것을 **SVI (Switched Virtual Interface)** 라고 부름.

```
interface vlan 10
  ip address 192.168.10.1 255.255.255.0
```

"VLAN 10의 게이트웨이를 이 스위치가 직접 담당하겠다"는 의미.
L3 스위치가 별도 라우터 없이 VLAN 간 라우팅을 처리할 수 있게 됨.

```
VLAN 10 (192.168.10.x) ─┐
                         ├─ L3 스위치 SVI → inter-VLAN 라우팅
VLAN 20 (192.168.20.x) ─┘
```

| 개념 | 계층 |
|------|------|
| VLAN 자체 (태그, 브로드캐스트 분리) | L2 |
| VLAN Interface에 IP 할당 (SVI) | L3 |
| SVI로 VLAN 간 라우팅 | L3 |

VLAN이 L3로 바뀌는 게 아니라, L3 스위치가 VLAN 위에 라우팅 기능을 추가로 얹는 것.
